# English and Hebrew

The site is bilingual. English is the bare address and Hebrew lives under
`/he`: `/blog` and `/he/blog` are the same page in two languages.

## How a page picks its language

- The address decides. `web/src/i18n/routing.ts` reads the prefix and sets
  `<html lang>` and `<html dir>` (`ltr` or `rtl`).
- One exception: a returning Hebrew reader who opens the bare English home page
  is sent to `/he`. Everywhere else the address wins.
- Text a reader or the author typed is rendered with `dir="auto"`, so English
  inside a Hebrew page lays out correctly.

## Interface strings

The interface's words are in tables under `web/src/i18n/` (`words.ts`,
`chrome.ts`, `pages.ts`, `admin.ts`, `statement.ts`), each with an English and
a Hebrew half. A Hebrew key that is missing is a type error, and the tests
reject an empty one. Every Hebrew string the site shows is listed in
[docs/hebrew/strings.md](../hebrew/strings.md).

## Content in two languages

- Structured copy (projects, the story, site copy) has an `{en, he}` pair per
  field.
- Notes and areas carry a Hebrew block beside the English.
- Each translation remembers a fingerprint of the English it was written from,
  so the site can tell **translated** from **stale** (the English changed
  since).
- A `/he` page that would only show English fallback is marked `noindex`, has
  no `hreflang`, and is left out of the sitemap.

In the admin, `/admin/translations` lists everything missing or stale, by type,
and every admin list shows a translation pill. The note editor shows English
and Hebrew side by side and can publish one language or both.

## Terminology

Technical terms follow an approved glossary,
[docs/i18n/hebrew-tech-glossary.md](../i18n/hebrew-tech-glossary.md), whose
machine-readable twin is `web/src/i18n/glossary.json`. Tests and lints read it,
and the admin uses it to advise while typing. It never blocks a save.
